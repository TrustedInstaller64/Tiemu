用户于 2026-11-03 明确要求继续 A：让世界状态长期驻留 C++，逐步迁移状态管理、出生演化和实体生命周期，同时排查永劫训练变慢并继续寻找单世界提速方案。沿用已确认的 A 方向，不重新请求架构或推送授权。

## 约束

- 分支为 `codex/single-world-a`；基线 `eca7377`（可执行代码 `26c1c26`）。C 保持独立、暂缓，不修改 main 或 AMPHOREUS。
- 全部项目执行、编译、测试、模型运行与性能测量仅在 GitHub 托管 runner。本机只做静态分析、文件编辑、Git 和小型证据处理；不安装 Docker。
- 保留 float64 世界数值、现有随机数消费及在线 optimizer 更新顺序，不使用 fast-math/FMA，不实施多世界实验产品功能。

- 继续验证 Windows 原生、Linux CPU/Docker 与云端 macOS。云端 macOS 不是用户 M1 的新实测。

## 方案与范围

选用显式同步的常驻 C++ World。核心持有连续数值与缓存状态、人口顺序、单调且不复用的实体编号、重复使用的工作区。Python 在明确的阶段边界导入当前公开字段，C++ 在自有状态上执行交互，Python 同步需要公开的结果。实体增删/重排由同一 World 对账处理；关闭/加载世界必须结束或重建原生生命周期。

仅缓存对象地址并跳过同步不可行：现有代码和外部调用可以原地修改 ndarray、缓存和标量。直接用 C++ 行视图替换 Python 数组也不采用：这会改变独立所有权、旧数组别名和替换语义。初期保留 Python 镜像，明确每个边界仍有 O(N) 检查/导入；后续迁移所有写入点后才能使用完整 dirty 协议。

云端首版测量后调整：出生后的成员更新使用 `reconcile`，只上传新增实体；C++ 在可复用的双缓冲中保留、删除和重排已有行。该操作将数值标记为过期，禁止 snapshot/交互，直到下一次完整同步；独立输入的出生计算仍可执行。交互失败是另一种更严格的错误状态，完整同步之前连出生和成员更新也拒绝。此区分避免重复打包全部存活实体，同时不把旧数值当成当前公开状态。

本轮把 `_add_new_entities` 的数值流水线移入一次 C++ 批调用，保留逐个命名与 NumPy normal 的交错顺序。legacy dot 仍遵循 NumPy 现有归约；新生保留 cache=None 和整型零派生字段，不能提前评分。标准内置对象以外、非有限值、共享/只读/非标准数组、替换随机数/方法、多 Python 线程等条件保守回退。进入原生修改后发生错误应终止，不能对部分修改后的状态重跑旧逻辑。

出生/删除/重排的原生生命周期需要真实接入正常世界运行。均值、百分位、heapq 平票、黄金裔排序、Guide 训练及特殊事件的决策暂留原顺序 Python；逐步迁移不等于一次重写整个世界。跨阶段持有数据不自动证明更快，接受与否由同机成对测量决定。

## 永劫诊断

A1→A2 的永劫管理器、实体和模型训练代码未变；实际变动包含小核 C ABI 和全局分布统计边界。先以冻结 A1/A2 同机旋转次序、多次完整真实训练阶段复测：原 200×2 与较长 200×12。单独诊断进程消融分布统计路径；计时运行不带观测包装，观测运行独立比较状态/RNG，记录实际 optimizer 步数。未获得证据前，不把 1～2 ms 差异归咎训练算法或硬件。
