# 单世界加速：A 主线与 C 长期实验

用户于 2026-10-30 批准继续实施：没有任何批量实验需求；A、C 必须分支隔离，以 A 为主；探索全面 Python→C/C++ 以及单世界中可以独立执行的多核任务。

## 约束和验收

- A 分支 `codex/single-world-a`：保留演化规则、每次交互和在线 optimizer step 顺序、原 RNG 消费、世界 float64 / 网络 float32。以固定原版和迁移前基线分别回放，不把有限样本等价当成任意长轨迹逐位证明。
- C 分支 `codex/experimental-c`：长期实验，不自动合并回 A；每项实验必须登记可能首次分歧的位置和下游影响。
- 不实现独立世界并行、参数搜索或批量实验调度。
- 本地禁止编译、测试、基准、训练、模型加载和 Docker 安装；仅做轻量编辑、静态读取、Git 和远端状态查询。重型验证仅在 GitHub 托管 runner 运行。
- 保留 Windows 原生、Linux CPU Docker/Hyper-V、Apple Silicon 支持。云端 macOS CPU 验证不等于用户这台 M1 的完整性能/Metal/ANE验收。

## 方案选择

A 被选为主线：先削减重复数据准备和原生边界，再迁移独立阶段。C 被选为长期目标：可探索低精度、批训练、GPU世界计算，但必须单独比较差异。独立多世界吞吐路线明确取消。

## 本轮 A 的具体交付

1. 融合纯化、潮汐、截断、归一化；有外部数组别名副作用的分支保留原路径。议会固定席位向量缓存兼容字典直接修改，抑制因子实时读取。投票模板按主导命途复用，实体累加顺序不变。
2. 增加 C++ `BatchEvaluator(workers=1, min_rows=4096)`，按独立实体行计算路径和概念评分，线程池按需创建并可关闭。`--native-threads`、`--native-min-rows` 独立于 PyTorch线程数。默认1线程；完整阶段数据支持后才调整默认。
3. 将固定全局分布后的评分阶段接入批处理。先取得原旧路径对应的 multiplier，然后按原规则清缓存、处理非有限值和写回；不重排交互、RNG和投票归约。
4. 永劫训练复用交互状态，抽样前向不构建梯度图，移除无用的计算图保留；Value/Actor前向、采样和更新顺序不变。
5. 提供计算日志模式，减少实际写盘与展示，不删除原日志参数求值中的 RNG/cache 副作用。建立远端有界性能与一致性记录。

## 全面 C/C++ 迁移路径

本轮迁移纯数值流程和独立评分调度。下一阶段依据完整人类、永劫训练、LLM和IO的远程剖析，把稳定实体编号、连续数值状态和更多事件调度迁往C++，Python保留外部模型/交互适配。迁移不意味着用不同的随机生成器替换 Python/NumPy，或合并依赖相邻状态的训练更新。全面移除Python是待验证方向，不能仅因语言不同就假定更快。

### A2：用户追加的无 pybind11 核心

用户随后明确要求重要运算模块完全 C++ 重写、不要 pybind11。据此核心改为可独立 CMake 构建的 C++17 共享库和 C ABI，Python 使用薄层 ctypes 数据适配。生产依赖删除 pybind11；历史 A1 基准可单独安装它以构建冻结对照。

无机网格段、两套 MT 状态推进及整代有序实体交互迁入核心；原 Python 循环保留作参考与非标准输入回退。在线模型后端、出生/演化外层编排、控制台和存档仍在 Python。独立 C 客户端、三平台回放、每次交互的随机状态轨迹和实际整阶段计时共同验收，不以“改成 C++”本身作为速度证明。实现和剩余瓶颈见 [A2 记录](../../a2-cpu-bottlenecks.md)。

## 差异登记

| 改动 | 可能出现分歧的位置 | A 的控制 | C 可研究方向 |
|---|---|---|---|
| 缓存/流程融合 | 旧路径读入时点、非有限值、外部数组别名 | 保留时序/别名边界并回放 | 状态结构和缓存规则重定义 |
| 多线程 | 共享写入、求和顺序、随机数消费 | 仅独立行并行，无随机数，顺序归约 | 同步批交互，改变状态可见时点 |
| SIMD/浮点 | 累加顺序、FMA、阈值/并列排序 | 严格浮点，行内顺序不变 | FP32/混合精度、fast-math，追踪首个分歧 |
| 训练 | 梯度/Adam状态、下一次抽样 | 每次更新与RNG顺序相同 | 批训练、更新频率和网络重构 |
| LLM | token采样、动作JSON、奖励与淘汰 | 保持模型设置/调用顺序 | 量化、小模型、生成上限、异步决策 |
| 日志 | 字节码日志消耗RNG，repr填充路径缓存 | 保留求值副作用，只降低输出 | 分离展示RNG，视为版本化规则变更 |

## 验证边界

远端先证明新增接口测试在旧核心上按预期失败，再运行新实现的全套回放和三平台CPU检查。比较1/2/4线程逐行输出，检查非法形状、关闭线程池、非有限值及状态污染。性能任务在同一runner比较冻结基线与A，输出机器信息、原始重复计时和完整作用域；不以共享runner单次耗时或小内核速度宣称完整世界倍率。
