# A5：按等价测速选择结构

本轮基线为 A4 `e8b73873e9938fd068196d54e26881cc36539750`，候选/测试提交 `0201f995d715c1985f8ab63ef462110be444e675`。目标是在保持等价性的前提下，按实际测速选择更快的候选。所有构建、项目导入、测试、模拟和计时都在 GitHub 托管 runner；文档整理只读取已完成任务的日志与证据。

## 当前瓶颈与长短永劫的边界

现有证据支持存在可优化的外围开销，不支持已经到达硬件性能上限。A4 的 Linux 10,000×3 人类观测中，完整交互入口约 252.5 ms，其中兼容/资格检查约 186.6 ms，C++ 交互本体约 10.1 ms；评分入口约 133.1 ms，其中 C++ prepare/finish 合计约 2.46 ms。这些观测区间存在嵌套，不能相加，也不能把外围时间全部称作解释器成本。此前的 242/9.5 ms 是 A2 的历史数据，方向仍有参考价值，但不应冒充 A4 新数据。见 [A4 剖析](performance/a4-profile-06353b7.json)。

“短样本慢”既不能推断“长样本必慢”，也不能推断“跑久就会变快”。固定成本可以摊薄，逐次成本会累积，而人口和实际训练工作量都会影响结果。同为 200 人口，A4 的 Mac 2 代与 12 代速度倍率分别为 0.908 和 0.902；不能拿 1,000 人口的 1.506 倍反驳这个观测。

更重要的是，1,000×12 的旧观测只有每个 optimizer 累计 44 次更新：第一代用原选择器，后 11 代传入的轮回者已不在人口中。静态追踪发现 `end_aeonic_cycle` 更换宿主只修改局部引用，`simulation.py` 和旧基准调用方没有接回它。该问题在上游 `691c6e0` 已存在，另一份基于上游 `5299d0c` 的外部实现也有同类缺口。本轮不修这个会改变旧结果的行为，不把保留它的快路径称作持续多轮训练加速。

当前 A 已在人口小于 512 或传入轮回者仍在人口中时保留原选择器；新索引没有在这两类路径默认执行。可继续比较完全恢复原 generation 循环能否减少外围分支成本，但不能预先认定它会修复 Mac 的约 10% 短场景回退。

## 外部提交源码对照

该外部提交以只读方式提供，其 Git bundle 的 `optimized-eval` 指向 `ae83de9e7c4122cc18aa7a11a61db2fb2f86913f`，不对应本仓库已发布分支。交付基线是上游 `5299d0c604d0b5353dcc0d0d75c871abb38e4d70`，A 保留其后继 `691c6e0` 的选人、重算和事件规则。两者的人类阶段不是同一工作，不直接用既有倍率排名。本轮仅借鉴邻居预计算思路。

| 方向 | 当前 A 的事实与判断 |
|---|---|
| 减少状态重建/复制 | 仍最值得深入；A3/A4 已有长期 World、稳定 ID、出生数值与评分缓冲，下一步应包括重复资格扫描和 Python 镜像同步，不能说“尚未开始常驻” |
| 预计算网格邻居 | A 当前每代仍作边界判断；作为单独 C++ 候选实测，必须计入建表成本，保留原地更新和求和顺序 |
| 主命途索引缓存 | 可研究，但 C++ 当前每次只扫 12 项，优先级低于外围检查；该外部实现的缓存不观察公开路径数组原地修改，不能直接照搬 |
| 席位缓存 | A 已有缓存及公开状态检查，A4 每批评分只刷新一次；该外部实现对公开 `seats/total_seats` 修改缺少等价失效，不产生可直接重复计入的收益 |
| 删除训练等待 | 该外部实现删的是有机阶段装饰性等待；A 在纯计算/非 TTY/快进模式已跳过，永劫本身没有这一等待 |

## 实验与验收方式

[A5 托管 CI 对照](https://github.com/TrustedInstaller64/Tiemu/actions/runs/41794212195)将两个独立实验放在同一平台的 runner 内顺序执行，默认构建与宏候选分目录。宏候选编译命令必须显式包含 `TIEMU_PRECOMPUTE_NEIGHBORS`，并先后通过默认/宏契约检查。未启用候选前，生产默认算法保持 A4。

- 永劫：同一 A4 源码/原生库，只替换冻结 A3 的 `run_aeonic_cycle_generation` 方法；当前、原循环、当前重复组涵盖全部六种进程顺序。初始 200/1,000 人口、2/12 代均分别测现有含轮回切换的 full-cycle 工作负载和受控持续训练。后者明确使用偏谈判的有限初始策略、没有换代或补回目标，保留真实采样、梯度和 Adam；人口会按原规则下降，既不是恒定人口的长训，也不代表完整世界。独立观察组逐代记录 live 引用、人口、实际更新和索引进入；最终及逐代状态、权重、完整 Adam、三种 RNG 必须严格一致。
- 无机：原分支、宏候选、同一原分支重复组；覆盖 1/2/10 网格的 1/100/10,000 步与 32 网格的 1/100 步，以及真实 10×10、10,000 代、每次最多 100 步的无机阶段。计入每次建表，内核检查完整网格与 MT 字节，真实阶段检查 legacy 和全部 RNG。邻居表常见 64 位布局约 72 字节/格，报告为布局估算而非实测 RSS。
- 计时与观察分开，保留全部样本和失败；同代码重复组估计波动。结果一致是前提，默认选型还要看真实阶段收益、不同规模损益及跨平台重复性，不能挑最快一次。

[默认回归](https://github.com/TrustedInstaller64/Tiemu/actions/runs/41794212208)本轮已补齐 macOS：Linux/macOS 各 613 通过，Windows 601 通过、12 项既有平台跳过；三平台独立 C、C ABI、单/四线程 CLI 与 Linux CPU Docker 均通过。本轮 Mac scoring math probe 的 3,089 行、10 种配置，保留标量 tanh 的表达式没有位差异。

此外，默认生产路径未启用宏的 [A4 场景复测](https://github.com/TrustedInstaller64/Tiemu/actions/runs/41794212221)与新结构消融分开归档。由于本次 Mac runner 已实际可用，又单独提交了一次 [冻结 A2/A3 诊断](https://github.com/TrustedInstaller64/Tiemu/actions/runs/41794495133)；不把过去未启动的尝试当性能数据。

## 测速与选型结果

**选择保留 A4 默认分流，不全面恢复旧永劫循环，不默认启用邻居表。** 本轮没有通过降低精度、改变训练规则或修复旧引用行为换取速度；宏候选仅保留为可复现的默认关闭实验。

### 原永劫循环与当前结构

三平台全部成功，24 个场景的最终及逐代状态/权重/完整 Adam/RNG 一致；受控组每代都保持 live 引用且两个 optimizer 均实际更新。[结构实验记录](performance/a5-aeonic-0201f99.json)保留全部 864 条纯计时原始样本和逐代观察结果。

以下为六个配对进程块中，**旧循环耗时/当前循环耗时**的中位数，大于 1 表示当前结构更快。每块先对两次原始样本取中位数；几何平均和全部分布也保留在 JSON 中，没有只取最好一次。

| 工作负载：初始人口×代数 | Linux | Windows | 托管 Mac |
|---|---:|---:|---:|
| 既有 full-cycle 200×2 | 0.997 | 0.991 | 1.134 |
| 既有 full-cycle 200×12 | 0.994 | 0.998 | 0.911 |
| 既有 full-cycle 1,000×2 | 1.128 | 1.060 | 1.346 |
| 既有 full-cycle 1,000×12 | 1.450 | 1.566 | 1.803 |
| 受控持续训练 200×2 | 0.999 | 0.997 | 1.014 |
| 受控持续训练 200×12 | 1.000 | 1.000 | 1.104 |
| 受控持续训练 1,000×2 | 0.998 | 1.009 | 0.983 |
| 受控持续训练 1,000×12 | 1.002 | 1.005 | 1.043 |

Linux/Windows 的受控训练接近持平，没有支持全面回退的稳定收益；在本次既有大人口样本中，保留索引的当前结构更快。Mac 多处波动过大，同代码重复对照在不同场景的极值达到 0.438～1.577，不能把表内小幅差异认作可靠优化。这里只保留既有条件化选择，不据此新增 Mac 专属分流。

受控四个场景每个 optimizer 分别真实更新 200、870、949、1,680 次，最终人口分别为 199、15、736、5；三平台此次相同。旧 full-cycle 200 人口两种长度均只有 15 次更新，1,000 人口均只有 44 次。这次直接验证了“代数长”与“训练次数多”不是同一个指标；原先 1,000×12 的收益仍不得称作持续多轮训练提速。

### 邻居预计算

默认编译的 34 条新契约在三平台全部通过；宏开启的完整套件为 Linux/Mac 各 613 通过、Windows 601 通过和 12 项平台跳过，实际编译命令已核对宏启用。所有完整网格/MT 和真实阶段 legacy/RNG 摘要一致。[邻居实验记录](performance/a5-inorganic-0201f99.json)保留 1,944 条原始计时，包含 594 条内核与 54 条真实阶段样本/平台。

下表为六块配对 **原实现耗时/邻居候选耗时** 的中位数，大于 1 才是候选更快；方向与上表的候选身份不同，不跨实验相乘。

| 场景 | Linux | Windows | 托管 Mac |
|---|---:|---:|---:|
| 实际无机 10×10、10,000 代，100 步分块 | 0.998 | 1.023 | 0.986 |
| 10×10 内核，单步调用 | 0.916 | 0.846 | 0.883 |
| 10×10 内核，100 步调用 | 0.996 | 1.035 | 0.909 |
| 10×10 内核，10,000 步调用 | 0.998 | 1.033 | 0.949 |

Linux 实际阶段六块比率为 0.992～1.009，Mac 为 0.890～1.066，均没有净收益证据。Windows 中位速度约提高 2.3%，但六块为 0.961～1.054，其中两块比原实现慢；同代码控制也有 0.890～1.030 的波动。再考虑单步速度约下降 15%（速度比 0.846），不足以支持默认或 Windows 全局启用。表构造包含在计时中，不把建立索引的成本排除后再宣称收益。

### Mac 旧回退诊断

[冻结诊断证据](performance/a5-macos-frozen-0201f99.json)本次成功：A3/A2 的配对耗时几何平均比在 200×2/×12 分别约为 0.944/0.857，旧的约 7.1% 短场景回退没有稳定复现。相同 A3 代码重复运行的比率区间分别为 0.831～1.169、0.692～1.192；不能把这一次反向变化宣布为“问题已修复”或可靠 A3 提速。

本次纯计时窗口的 GC 收集计数全部为零，观察的 World 构造/出生/reconcile/打包调用也为零。它们只排除这一个 fixture 在这些窗口内对应直接执行成本，不排除初始化对后续对象布局的间接影响，也不确认温控、宿主调度、频率或通用 GC 根因。runner 自报 Apple M1 (Virtual)、3 vCPU、7 GiB，不是物理 M1 的新测速。

另一次 [默认 A3→A4 复测](performance/a5-default-0201f99.json)也保留全部不利观测：Mac 的 200×2 由上轮 0.908 变为本轮 1.721，而 200×12 为 0.784、512×2 为 0.620、人类 1,000×6 为 0.722。该旧比较与上面的同 checkout 结构消融是不同实验，不用它覆盖后者的计时，也不据此宣布 Mac 普遍更快。

## 后续优先级

本轮测量支持继续把重点放在重复资格检查、状态导入/写回和共享模型检查去重上；邻居表及全面恢复旧循环没有提供更好的综合默认方案。主命途缓存可在受控原生状态内继续研究，公开数组失效语义必须保留。若要修复轮回者引用缺口，需要把行为修复与性能迁移分开验收，并重新建立持续多轮训练基线。本轮未实施这些后续改动。
