默认仍保留单线程。Linux 万人演化四线程相对 C2 单线程快约 4.75%，但同次运行中两个关闭实验且末态相同的版本也出现约 11.4% 耗时差；这表明短样本存在明显波动，不是对噪声建立了置信区间。Windows 千人场景增加线程反慢，云端 macOS 千人场景更有利于多线程，万人场景则仍是单线程较快。Mac 万人场景的冻结 C1 与候选仅 C1 末态相同但耗时也相差约 11.4%，C2 相对冻结 C1 实际仅为 1.010～1.025×，不能将相对同版开关的全部差值都当作确定收益。Mac 运行器仅暴露 3 个逻辑 CPU，四线程预算不能称为占满四个物理核，更不能外推到用户 M1 或双路 Xeon。

预打包冷池调用中，万人出生数值行可以受益于并行，千人调用则因调度启动反而更慢。数值核心的时间远小于完整出生入口，不能把其倍率当作整体倍率。当前证据支持批量 C++ 迁移；尚不足以给出跨平台稳定的默认多线程配置。

进一步核对已有云端计时：Linux/macOS 全演化阶段在四线程预算下，进程 CPU 时间/墙钟时间的样本中位数仍仅约 **1.0006～1.0075**，即整个测量窗口的平均进程用量仍接近一个 CPU，未形成持续多核占用。这也限制了对 Mac 千人场景较好墙钟数字的因果解释，不能断言其约 23% 的 C2 四线程/单线程差值全由并行计算贡献。Windows 短出生样本出现零或量化的 CPU 时间，不能据此解释成没有 CPU 工作。[派生比值及原数据出处](performance/c2-cpu-time-ratios.json)单独保存；这不是新的性能实验，也不是 Python 解释器占比剖析，不能据此认定“95% 都耗在解释器”。

**当前完成的偏差范围：** 15 组小人口原版轨迹（Linux/Windows 各两场景×三种子，macOS 无轮回者三种子），另有 Linux/Windows/macOS 各一组万人原生对照。孤立出生为另列的 4 个平台/规模样本，不加进轨迹组数。

- C2 与 C1：这 18 组轨迹的所记录检查点未发现新增数值、离散、RNG 或网络变化；末态评分、亲和度、缓存路径、网络/Adam 的最大误差为 0。
- C2 的 1/2/4 线程：已完成样本的末态摘要相同，重复计时进程也一致，未发现检查点分叉。
- 相对原版：15 组小人口轨迹未发现离散/RNG/网络分叉；末态评分最大绝对误差 3.55e-15、泰坦亲和度 4.44e-16、缓存路径 1.67e-16、所记录管理器数值 8.88e-16，首次微小数值差均在初态，来自既有迁移。蓝图、思潮和网络/Adam 的已检查末态误差为 0。
- 相对 A2：末态评分最大绝对误差 8.88e-16，首次微小差出现在第一代交互后，与既有 C1 变化一致。
- 路径分布 TV、席位 L1、人口数差均为 0。小人口相对原版的评分均值/标准差之差均为 0，q95 差最高 1.78e-15；万人相对 A2 的标准差之差最高 2.22e-16。相对原版的评分 Wasserstein 距离最高约 1.18e-16。非零 KS 约 1/N，不能解释为同百分比的演化错误。
- 孤立出生的名字/映射、整数零评分、空缓存、数组独立所有权等检查通过。其原版对照快照也包含旧实体；旧实体的微小分数差不是新生实体零分被改变。

以上为有限检查点与短阶段证据，并非完整内部状态、逐交互、长期统计或任意参数等价证明。接受范围仍未由诊断容差代替用户决定。

## 实现范围

本轮由用户明确要求在 C 路线上继续，允许结果离散并探索更大范围 C++ 改写。分支为 `codex/c2-newborns-parallel`，从已验证 C1 `7305af8` 分出；A 与 C1 保留。新增开关 `--experimental-c-newborns` 默认关闭，可与 `--experimental-c-scoring` 独立组合。

生产代码候选 `d32edce`，`5e4f944` 仅登记云端工作流，`8939363` 仅修正测试隔离。所有构建、运行、测试与测量均使用 GitHub 托管机器，本地只进行静态检查、编辑与 Git 操作，未安装 Docker。

出生数值流水线整体进入独立 C++17/C ABI：蓝图加随机扰动、构造时裁剪、遗产加成、纯化、潮汐、再次裁剪和归一化。保留 float64、原有归约与运算顺序，不使用 pybind11 或 fast-math。固定遗产向量的原 NumPy dot 在一批内复用一次。

Python 每名实体仍依次执行一次唯一姓名生成和一次原形状的 NumPy 正态抽样，随后 C++ 批量处理独立行。初始化字段共用一处实现，每名实体保留整数零评分、空路径缓存、独立数组与火种集合；人口追加与名字映射顺序保持。初始建群、增长补充及普通补员共用这条路径。

名字冲突重试和随机数高斯缓存均有契约测试。自定义构造/纯化/标准随机接口等不能安全批处理时保守回退；批处理已经消耗随机数后若失败，直接报告错误，不重跑标量循环。批次中间的实体发布延后到 C++ 返回以后，出生进行时不支持外部线程并发观察或修改这些容器/数组。

## 多线程如何应用

出生与 C1 评分复用同一个持久 C++ 线程池，按连续实体行分片。线程预算包含调用线程；不会每个实体创建线程，也不会分别建立两个池。姓名、随机抽样、注册实体和有依赖的逐次交互/优化器更新仍按顺序进行。

默认 `--native-threads 1 --native-min-rows 4096`。验证中 C2 的 1/2/4 线程均使用阈值 1，强制检验小批次的调度成本；这些是探索配置，并非自动修改默认值。整阶段的多线程比较同时改变出生与评分的线程预算，不能将所有增益归为出生。

```bash
python -m main --disable-llm --no-interactive --backend cpp --device cpu \
  --experimental-c-scoring --experimental-c-newborns \
  --native-threads 4 --native-min-rows 1
```

这是供目标运行环境使用的示例，本轮没有在用户 Mac 执行。

## 对照与计时边界

- 原版 `691c6e0023a83513ad3cd386cfee2198317104d3`，冻结 A2 `eca7377c6ee53ab1f57c32fd8227c31e0d73b1cb`，冻结 C1 `7305af8e8c8e03bec06adec2f5efdc4742974a4a`，均在同一 runner 现场运行。
- 候选两个实验都关闭必须与 A2 末态摘要相同；仅开启 C1 必须与冻结 C1 相同。C2 开启后的变化完整报告，不据参考容差替用户决定接受范围。
- 小人口：1,000×6 代，有/无轮回者，种子 731、42、2026；比较原版、A2、C1、候选关闭/仅 C1、C2 1/2/4 线程。
- 大人口：10,000×6 代，仅原生版本，seed 731；没有此规模的原版速度倍率。
- 独立出生：固定已有 1,000 个实体，新增 1,000/10,000 个，使用非零且含正负值的遗产与潮汐；计时包含分布准备、姓名、RNG、对象构造及写回。
- 每项三个 seed731 无观察计时样本取中位数，轮换进程执行顺序；多种子仅为有限轨迹检验，不是用户产品的批量实验功能。

轨迹计时排除初始化、模型启动、观察快照与进程启动。C2 初始建群已经使用线程池，因此演化和独立出生入口复用初始化的热池。另测预打包原生调用边界：新建冷池，包含输出分配、FFI、首次工作线程启动与完成，不包含输入准备或句柄构造；这不能替代完整出生或完整程序倍率。

观察器在初态、每代交互后和生长后抓取原字段；同配置观察/无观察末态摘要必须相同。每代另核对出生请求行数与原生处理行数，初始化调用不能掩盖生长回退。独立出生仅在入口前后抓取快照，单列结构与 RNG 对照，不冒充逐代观察器门控。

评分误差、实体亲和度、路径分布 TV、人口差、席位差、RNG、网络/Adam、首次分叉等沿用 [C1 比较定义](c1-speed-and-divergence.md)。最大数值误差为各样本末态指标；首次差异只精确到所记录检查点。发生离散或 RNG 分叉后，因名字可以复用，停止个体一一对应的数值比较；`numeric=null` 不表示零误差。轨迹分叉后的耗时可能对应不同实际工作量。

## 更大范围 C++ 重构的下一步

本轮的关键收益来自批量迁移，尚未把整个世界改成 C++ 常驻状态。命名、随机抽样调用、Python 实体生命周期、每代资格检查/数组打包/写回仍然存在。继续堆线程无法覆盖这些串行部分。

下一轮应先对 C2 的实际演化阶段单独剖析，再优先考虑合并人口统计/精英筛选和同一只读阶段的路径计算；长期方案是 C++ 持有稳定实体句柄和连续人口状态、Python 通过明确接口读写。迁移所有写入入口后才能减少反复扫描，直接删掉资格检查会漏掉外部数组替换、共享别名和自定义回调。

若继续把命名和随机抽样移进 C++，须显式复现 Python 命名抽样及 NumPy MT/高斯缓存的消费顺序，不能把换 RNG 或按线程分流伪装成保持随机顺序。交互和训练更新存在前后依赖，若另做改变提交顺序的并行实验，应使用独立开关与同一套分叉记录。上述内容是后续候选，未冒充本轮已实现或已测得的增益。
